# 서비스소개서 다운로드 폼 기획

작성일: 2026-10-15 · 상태: **테스트용 1차 구현 완료 (2026-10-16) — GAS 배포·PDF URL 대기**

## 목적

외부 DB 회원 대상 홍보메일의 [서비스소개서 다운로드] 버튼 → 폼 작성 페이지 → 작성 시 Resend로 자료 링크 메일 자동 발송.
신청자 정보는 세미나 신청과 같이 **구글시트에 저장**하고, **어느 메일(캠페인)에서 들어왔는지**도 함께 기록한다.

## 확정 사항

| 항목 | 결정 |
|---|---|
| 폼 형태 | 팝업 X — **독립 페이지** (`/seminar/downloadform`), 참고: recatch 리포트 다운로드 페이지 |
| 자료 전달 | PDF를 회사 서버에 올리고 **다운로드 링크(URL)를 메일 본문에** 넣어 발송 (첨부파일 X) |
| 중복 신청 | **차단하지 않음** — 같은 사람이 다시 신청해도 매번 저장 + 메일 재발송 |
| 유입 추적 | 홍보메일 버튼 링크에 UTM 파라미터를 붙이고, 폼 제출 시 시트에 함께 저장 |
| 폼 항목 | 추후 전달 예정 |

## 전체 흐름

```
홍보메일 [서비스소개서 다운로드] 버튼
  → https://hr.assesta.com/seminar/downloadform?utm_source=...&utm_medium=email&utm_campaign=...
  → 폼 작성 · 제출
  → POST /api/download-request (서버)
       ① 입력값 검증
       ② GAS(doPost, action: "download") → 구글시트 `downloads` 탭에 행 추가
       ③ Supabase 백업 저장 (실패해도 사용자에게는 성공 처리 — 세미나 신청과 동일 정책)
       ④ Resend로 자료 링크 메일 발송
       ⑤ 발송 결과(발송/발송실패)를 GAS로 2차 전송해 시트 갱신
  → /seminar/downloadform/complete
       "메일로 자료를 보내드렸어요" 안내 + [세미나 보러가기] 버튼 → /seminar
```

## 유입 추적 (어느 메일에서 들어왔는지)

- 홍보메일마다 버튼 링크에 UTM을 다르게 붙인다. 예)
  - `?utm_source=외부DB명&utm_medium=email&utm_campaign=2026-11-service-intro`
- 폼 페이지가 URL의 `utm_source / utm_medium / utm_campaign / utm_content`를 읽어 숨은 값으로 함께 제출
- UTM 없이 직접 들어온 경우 → `direct`로 저장
- 같은 탭에서 페이지 이동 후 돌아와도 유지되도록 sessionStorage에 보관 (첫 유입값 기준)
- **단축링크 사용 가능** — 메일별로 UTM이 다른 긴 URL을 만들고 각각 단축링크로 변환 (리다이렉트 시 쿼리 유지됨). 생성 후 클릭해서 주소창에 UTM이 남는지 반드시 확인
- 네이밍 규칙: 영문 소문자·숫자·`_`만 사용, 값 목록을 미리 표로 고정
  - `utm_source`=외부DB/업체, `utm_medium`=`email` 고정, `utm_campaign`=발송회차·주제(예: `2611_service_intro`), `utm_content`=메일 버전/버튼 위치(예: `a`, `top_btn`)
- 단축링크 서비스 클릭 수는 메일 보안 스캐너 때문에 부풀 수 있음 → 성과는 시트 신청 수 기준
- (선택) 수신자 개인 단위 추적: 홍보메일 발송 툴이 치환 태그(예: `{{id}}`)를 지원하면 `&rid={{id}}`를 붙여 저장 가능

| 구분 | 파일 | 비고 |
|---|---|---|
| 폼 페이지 | `app/(sub)/seminar/downloadform/page.tsx` | 정적 경로라 `[slug]`보다 우선 매칭 — 충돌 없음 |
| 완료 페이지 | `app/(sub)/seminar/downloadform/complete/page.tsx` | `/seminar` 이동 버튼 |

| 메일 템플릿 | `lib/download-email.ts` | `lib/seminar-confirmation-email.ts` 스타일 재사용, 다운로드 버튼(URL) 포함 |
| 설정 | `lib/download-config.ts` | 자료 URL · 페이지 문구 · 폼 옵션을 한 곳에서 관리 |
| GAS | 기존 Apps Script (레포 외부) | `doPost`에 `action: "download"` 분기 + `downloads` 시트 탭, 기존 `updateMailStatus` 재사용 여부 검토 |
| Supabase | `download_requests` 테이블 신규 | 백업용, 생성 필요 |

## 구글시트 `downloads` 탭 컬럼 (초안)

신청ID · 신청일시 · (폼 항목들 — 추후 확정) · 개인정보동의 · 마케팅동의 · utm_source · utm_medium · utm_campaign · utm_content · 메일발송상태

## 제약 / 불가 · 주의 사항

1. **메일 안에서 폼 띄우기 불가** → 버튼은 폼 페이지 링크 (확정 반영됨)
2. **자료 URL은 공개 링크** → 링크를 받은 사람이 전달하면 폼 없이도 다운로드 가능. 막으려면 만료형 링크 등 별도 개발 필요 (현재 범위 외)
3. **회사명 자동 검색(사업자번호 조회)** — 참고 페이지의 기능은 외부 기업정보 API 계약이 필요. 기본은 일반 텍스트 입력으로 구현
4. **업무 메일만 허용** — naver/gmail 등 개인 도메인 차단은 가능 (적용 여부 결정 필요)
5. **Resend 발송 한도** — 사용 중인 요금제의 일/월 발송 한도 확인 필요 (무료 요금제는 일 100통 수준). 홍보메일 반응이 크면 한도 초과 시 메일 발송실패로 기록됨
6. **발신 도메인** — 현재 `noreply@mail.piccle.ai`. ASSESTA 명의로 보내려면 Resend에 assesta 도메인 인증(DNS 레코드 추가) 필요
7. **홍보메일 자체의 법적 요건(정보통신망법)** — 외부 DB가 광고 수신 동의를 받은 명단인지, 제목 `(광고)` 표기, 수신거부 방법 포함 여부 확인. (폼 작성 후 자동 발송되는 자료 메일은 신청자 요청에 따른 것이라 광고 메일 아님)
8. GAS 코드는 레포 밖에 있으므로, 추가 코드를 전달하면 Apps Script 편집기에 붙여넣고 **새 버전으로 재배포** 해야 반영됨

## 자료 목록 시트 관리 전환 (2026-10-16)

- 자료 목록을 코드 배열 → 신청 DB 스프레드시트의 **`resources` 탭**으로 이전. 메일 발송 담당자가 시트에서 직접 추가·수정
  - 칸: `slug`(홍보메일 `?topic=` 값, 한 번 쓰면 변경 금지) · `자료명` · `pdfUrl` · `노출`(Y/N) · `메모`
- 사이트는 같은 Apps Script 웹앱에 `action: "listResources"`로 목록을 읽음 → **환경변수 추가 없음**
- 서버에서 1분 캐시, 시트 읽기 실패 시 마지막 성공 목록 사용. 한 번도 못 읽었으면 폼 대신 "신청 가능한 자료집이 없어요" 표시 (잘못된 PDF 링크 발송 방지)
- 형식이 틀린 행(slug 규칙 위반, 빈 자료명, http로 시작하지 않는 링크)은 폼에 노출하지 않음
- 배포 순서: **Apps Script 새 버전 재배포 + setupResourcesSheet 실행 → 사이트 코드 배포** (순서가 바뀌면 그 사이 폼이 비어 보임)
- 발신 주소 기본값을 `noreply@hr.assesta.com`으로 정정 (실제 Resend 인증 도메인. `mail.piccle.ai`는 미인증)
