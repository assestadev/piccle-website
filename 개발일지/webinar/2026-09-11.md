## 주요 설계 결정
1. **웨비나 전용 헤더 신규 제작(WebinarHeader)** — 메인 사이트 공용 `SiteHeader`를 수정하지 않고 별도 컴포넌트로 분리. 기능은 실제 피클 사이트의 서브페이지와 동일하게 "세미나"(현재 위치, 클릭 시 목록으로) + "문의하기" 버튼만 노출. 디자인은 프로토타입을 그대로 베끼지 않고 sticky+블러 배경 등 새 형태로 제작.
2. **로고: 피클 → ASSESTA 로 교체, 원본 자산은 보존** — 헤더 로고, 웨비나 카드/히어로/상세 안의 "브랜드 마크" 위치 전부 `lib/webinar-brand-config.ts`의 상수를 통해 ASSESTA 로고(`assesta-logo-dark.svg`)를 사용. `piccle-logo-mark.svg`는 삭제하지 않고 `public/webinar-assets/`에 남겨둠 — 나중에 되돌릴 때는 설정 파일 상수만 교체하면 됨.
3. **콘텐츠 데이터 공백 처리** — 두 번째 웨비나(`org-culture-diagnosis`)는 원본 프로토타입에 상세 콘텐츠(행사 안내·아젠다·프로그램·추천 대상)가 없어(카드/히어로용 요약 정보만 존재) 상세 페이지에 "콘텐츠 담당자로부터 전달받는 대로 업데이트될 예정" 안내 문구로 대체. 임의로 내용을 지어내지 않음.
4. **신청 폼 제출은 아직 저장소 연동 없음** — `components/webinar/registration-form.tsx`는 클라이언트 검증(관심주제 1개 이상 체크 등, 인계서 05-1번 로직 포함)까지만 구현하고, 통과하면 바로 `/webinar/[slug]/complete`로 이동. Google Apps Script POST + Resend 메일 발송 자리에 `TODO(GAS 연동 예정)` 주석으로 표시해둠 — 다음 단계에서 이어서 작업.
5. **마케팅 동의 고지 문구는 임시 하드코딩** — 인계서 06번 `marketing_consent_notice` 시트가 아직 없어 프로토타입 문구를 그대로 코드에 하드코딩. 시트 연동 시 `registration-form.tsx`의 `MARKETING_CONSENT_NOTICE` 상수를 props/fetch로 교체해야 함.

## 열려있는 결정 사항 (사용자 확인 필요)

## 추가 변경 5차 (같은 날, 신청 폼 → Google Apps Script 연동 시작)
사용자가 구글시트(`registrations`, 17개 컬럼 — 인계서 06번과 정확히 일치 확인함)를 만들고 `doPost` 초안을 공유함. 리뷰해서 아래 3가지 실질적 문제를 발견해 Next.js 쪽은 직접 수정, Apps Script 쪽은 수정된 코드를 전달함(에디터에 직접 접근할 수단이 없어 붙여넣기 방식으로 안내):

**Apps Script 코드에서 발견된 문제(수정 코드는 사용자에게 별도 전달)**
1. `LockService` 없음 — 동시 제출 시 중복 신청 차단(3단계)이 무력화될 수 있음(인계서 06번에서 이미 경고한 부분).
2. 중복 신청 검사 로직 자체가 없음 — 항상 새 행만 추가됨.
3. 인증/시크릿 검증이 전혀 없음 — 배포 URL만 알면 누구나 시트에 쓸 수 있는 상태.
4. 신청ID/신청일시가 초 단위(`HH:mm:ss`)라 같은 초에 처리된 두 건이 같은 값을 가질 수 있음 → 밀리초 단위로 변경 필요.
5. 대상 시트를 못 찾으면 조용히 "현재 활성 시트"로 폴백 — 나중에 탭을 잘못 클릭해두면 엉뚱한 시트에 쌓일 수 있어 위험. 명시적 에러로 바꿈.

**Next.js 쪽에 직접 구현한 것**
- `app/api/webinar-registration/route.ts` 신규 — 서버에서만 GAS 웹앱 URL과 공유 시크릿을 알고 호출(클라이언트는 절대 모름). 필수값/관심주제/개인정보동의 서버 검증 포함. GAS 응답이 `duplicate`면 409로, 저장 성공이면 200으로 응답.
- `components/webinar/registration-form.tsx` — 기존 `setTimeout` 스텁을 실제 `fetch("/api/webinar-registration")` 호출로 교체, 에러 메시지 표시(문의폼과 동일한 패턴) 추가. `seminarType`/`eventDate` props를 상세 페이지(`app/(sub)/webinar/[slug]/page.tsx`)에서 새로 전달받도록 함.
- `.env.local.example` 추가(커밋 가능, 실제 값 없음), `.env.local`에 시크릿 값 미리 채워둠(로컬 전용, gitignore됨) — `GAS_WEBINAR_WEBAPP_URL`은 사용자가 배포 후 채워야 함.

- Apps Script 웹앱은 서버-서버 호출(Next.js → GAS) 특성상 "나만" 접근 권한으로는 동작 불가 → "모든 사용자"로 배포하되 공유 시크릿(공식 발급, Script Properties에만 저장)으로 실질적 인증을 대체하기로 함.
- 반면 구글시트 자체(데이터 열람)는 일반 Drive 공유 설정으로 특정 계정(`assestamedia@gmail.com`)에게만 제한 가능 — 이 부분은 사용자가 시트 "공유" 설정에서 직접 처리해야 함(Claude가 Drive 권한을 대신 바꿀 수단 없음).
- **중요 발견**: 리뷰 중 로그인 없이 시트 헤더 행을 CSV로 읽어올 수 있었음 — 즉 현재 공유 설정이 "링크가 있는 모든 사용자"로 열려 있다는 뜻. 개인정보가 쌓이기 전에 "제한됨"으로 바꾸도록 안내함.

**검증**: `tsc --noEmit`, `eslint app components lib`(기존 무관 경고 1건 제외 통과), `next build`(새 라우트 `/api/webinar-registration` 정상 포함) 전부 통과. GAS 웹앱 URL이 아직 없어 실제 저장까지는 End-to-End 테스트 못함 — URL 받으면 이어서 확인 예정.

## 추가 변경 6차 (같은 날, GAS 웹앱 배포 후 실사용 데이터 인코딩 진단)
사용자가 Apps Script를 웹 앱으로 배포(우여곡절 — Google 계정 보안 검사 화면, "Google hasn't verified this app" OAuth 동의, 여러 계정 로그인 충돌로 인한 "파일을 열 수 없습니다" 에러를 순서대로 겪고 해결함). 배포 URL을 받아 실제 연동 테스트:
- **버그 발견 1**: `SpreadsheetApp.getActiveSpreadsheet()`가 `null` 반환 — 이 Apps Script 프로젝트가 시트에 종속된 컨테이너 바인딩 스크립트가 아니라 독립 실행형(standalone)이라 "활성 시트" 개념이 없어서 발생. `SpreadsheetApp.openById(SPREADSHEET_ID)`로 명시적으로 열도록 수정한 코드를 전달, 재배포 후 정상 저장 확인.
- **버그 발견 2 (오진단으로 판명)**: 시트에 저장된 한글이 깨져 보인다는 리포트 → 원인 조사 결과 실제 서비스 코드/데이터 경로 문제가 아니라, 제가 진단용으로 실행한 **Windows Git Bash `curl -d` 명령어의 터미널 코드페이지 문제**였음(명령줄에 직접 타이핑한 한글이 UTF-8이 아니게 인코딩됨). Node `fetch()`(브라우저와 동일한 인코딩 방식)로 재현 시 한글/영어/숫자 혼합 데이터 모두 깨지지 않고 정상 저장됨을 확인. 그래도 방어적으로 두 fetch 호출(`registration-form.tsx→API route`, `API route→GAS`) 모두 `Content-Type: application/json; charset=utf-8`을 명시하도록 코드에 고정.
- **보안 강화 논의**: 사용자가 구글시트 열람을 `assestamedia@gmail.com` 계정으로만 제한하고 싶다고 함 → Drive "공유" 설정을 "제한됨"으로 바꾸는 방법 안내(Claude가 대신 바꿀 수단 없음, Drive 권한 API 미보유). 리뷰 중 실제로 CSV export가 로그인 없이 읽혔던 걸 근거로 그 시점엔 "링크가 있는 모든 사용자"로 열려있었음을 지적 — 이후 사용자가 제한 조치를 취한 것으로 보임(이후 같은 export 시도가 401로 막힘, 재확인은 못 함).

## 추가 변경 9차 (같은 날, Supabase 이중 저장 + Resend 메일 발송 연동)
사용자 요청: "구글시트 말고 이중으로도 저장하고 싶다" + "Resend로 안내메일 개발".

- **Supabase 이중 저장**: `app/api/webinar-registration/route.ts`에 구글시트 저장 성공 후 같은 데이터를 `webinar_registrations` 테이블(신규, 기존 `inquiries`와 같은 프로젝트 재사용 전제)에 추가 저장하는 로직 구현. 실패해도 신청 자체는 성공 처리(로그만 남김) — 구글시트가 source of truth, Supabase는 백업 용도. 테이블 생성 SQL(anon insert-only RLS 정책 포함)을 사용자에게 전달함 — **아직 크리덴셜(`NEXT_PUBLIC_SUPABASE_URL`/`ANON_KEY`)을 못 받아 로컬에서는 계속 스킵되는 중(설계대로 non-blocking)**.
